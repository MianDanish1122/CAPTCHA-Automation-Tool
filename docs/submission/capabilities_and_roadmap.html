CAPTCHA Inspector - Capabilities, Requirement Coverage and Roadmap

Technology Brainz assignment · status of the current build

1. What the tool does today

CapabilityCurrent behaviour
Import the CSVReads the 200-row CSV, validates it, keeps every column, reports bad rows with their row number, normalises the expected CAPTCHA label.
Open Contact Us pagesReal headless Chromium (Playwright); waits for the page to settle; reads the rendered page, scripts and iframes.
Identify CAPTCHAsGoogle reCAPTCHA (v2 / invisible), hCaptcha, Cloudflare Turnstile, and other anti-bot challenges; records the type and widget state; ignores mentions that appear only in static code.
Keep the workflow movingA CAPTCHA never blocks the batch: it is recorded with a screenshot, queued in Human Review, and the scan continues with the next site.
Compare with the CSVExpected vs Detected: Match, Mismatch, Not detected, Not accessible, Not verified. Percentages use only inspected rows and state the sample size.
Inspect forms safelyCounts forms and fields; never clicks CAPTCHAs, never submits forms, never collects tokens.
Solve text CAPTCHAsOCR pipeline for our own synthetic text CAPTCHAs (about 99.3% on our own generator).
Verify tokensCalls the providers' official verification service with their published test keys and records the real answer.
ReportsAudit report and Expected-vs-Detected report (CSV / Markdown), safe against spreadsheet formula injection.
Safety and auditDomain allow-list, SSRF protection, robots.txt respected, request pacing per host, role-based login, tamper-evident audit trail.

2. Requirement coverage

Requirement (from the assignment message)StatusNotes
Import the 200-row CSVMetTested with the assignment's column layout.
Use PlaywrightMetAll page inspection runs through Playwright Chromium.
Work with Contact Us formsMetUses the CSV's Contact Page value; discovers contact pages from a home page when asked.
Identify the CAPTCHA challengeMetProvider, type and state; checked on fixtures and on real sites.
CAPTCHA must not prevent the workflow from proceedingMetRecorded, queued for a person, batch continues. Unreachable sites are reported, not fatal.
Handle different CAPTCHA typesPartlyAll major types are identified and handled by routing to a human. Automated solving exists only for our own text CAPTCHAs.
Solve third-party CAPTCHAs (reCAPTCHA, hCaptcha, Turnstile)Not done, by designBypassing them would breach the providers' terms and the websites' access controls. Not implemented.
Work on all 200 websitesPartlyEvery row gets a result. Sites that block automated browsers, forbid crawling in robots.txt, or time out are reported as "Not accessible" with the reason. A full 200-site run has not been completed yet; the live sample so far is small (4 sites: 2 inspected and matching, 2 not accessible).
Real-time usePartlyWorks locally and can be hosted; a live deployment and allow-list for the 200 domains still have to be set up.
Overall. The detection, evidence, reporting and non-blocking workflow parts are complete and tested (backend suite: 630 passed, 1 skipped, 0 failed; browser suites 30/30, 32/32, 19/19, 16/16 at the last full run). The one requirement that is not met is automated solving of third-party CAPTCHAs, and the share of the 200 sites that can be inspected depends on how many allow automated access.

3. Known limits

LimitWhy
Some sites show "Not accessible"Bot walls, 403/429 responses, robots.txt disallow, timeouts. The tool stops rather than evading them.
No automatic solving of reCAPTCHA / hCaptcha / TurnstileLegal and terms-of-service reasons; a person reviews each one.
Confidence per page is not shownIt is not measured, so the screens show "-" instead of an invented number.
Small live sampleThe real-site results so far are not a statistical accuracy claim.
Local-only until hostedNo public link exists yet.
